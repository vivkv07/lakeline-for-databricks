1Workspace

Choose the Databricks workspace for this cost connection. There is one connection per workspace URL. When more than one workspace is listed, pick one yourself — the extension never switches workspaces on its own.

Workspaces found in this browser

Supported hosts: *.cloud.databricks.com, *.azuredatabricks.net, *.gcp.databricks.com. Account-console URLs are not workspaces.

2Site access

The extension runs only on workspaces you allow. Access is requested for exactly the selected workspace URL, nothing broader.

3Sign-in

How should the extension query Databricks?

Local helper

  1. Run start-helper.command from the project folder (double-click it on macOS, or run npm run helper).
  2. The helper's setup page opens and pairs with this extension automatically.
  3. Come back here, choose your workspace above, and select Sign in. Databricks opens its sign-in page in your browser.

Monitor sign-in (optional, broader access)

The run monitor needs its own sign-in. It requests the all-apis scope on a separate, dedicated profile. The extension uses it only for read-only run, pipeline, SQL warehouse and cluster status, and the helper forwards only an allowlist of read-only requests. Cost queries keep using the SQL-only sign-in above.

Can't use the setup page?

Paste the 24-character pairing key printed in the helper's terminal window. Use this only when the setup page can't reach the extension. The key is checked with the helper before it is kept, and it is cleared when the browser closes.

24 characters: digits 0–9 and letters a–f.

Personal access token

Kept in session storage for this browser session only (cleared when the browser closes) and never shown again. Use a token for an identity that can use the SQL warehouse and read the billing tables — nothing more.

4SQL warehouse

Cost queries run on one SQL warehouse per workspace. Automatic picks a running warehouse first, then the smallest size, and is resolved when you save — never switched per query.

Listing a warehouse doesn't prove that you have CAN USE on it or read access to the billing tables. The first cost query may still fail; its error names what is missing.

5Billing source

Only these two tables are supported. No silent fallback between them: if the selected table isn't available, you'll see a specific error.

Three-letter code that matches currency_code in the price table. Amounts are never converted.

Advanced: data sources

Use the system tables, or an approved view with the same columns in your own catalog (catalog.schema.view, outside the system catalog).

6Save

Disconnect

Removes the saved cost connection and the session token for this workspace. Workspace colors and other workspaces are not changed.

Local import

Load per-workspace, per-resource summaries from a costs.json file for Local import mode. The file is validated and stored in this browser; imported summaries contain only what you import — no query history or run detail.

Fields per entry: workspace, type, id, periodDays (7, 30 or 90), currency, total, previous, basis, owner, allocation, updatedAt, coverageEnd, daily [{date, cost}]. See costs.example.json in the project folder for the format.

Diagnostics

The last errors, with secrets removed. No SQL text, query results, or tokens are recorded.

    What the extension stores and where
    WhereWhatCleared by
    Browser local storage Settings (mode, period, show costs, monitor preferences); one connection per workspace (URL, workspace ID, sign-in type, price table, currency, data sources, warehouse choice — never tokens); workspace IDs seen in tabs; your imported summaries; recent sanitized errors. Disconnect, Clear import, Clear diagnostics, or removing the extension.
    Browser local storage (separate) Workspace colors, kept apart from billing so connecting or disconnecting never changes them. Reset in the popup's Workspace colors panel, or removing the extension.
    Session storage (memory only) Personal access tokens, the helper pairing key, and the popup's one-time "connect this workspace" hand-off. Closing the browser, Remove token, Forget helper pairing.
    Databricks CLI (outside the extension) The helper's browser sign-in, in dedicated CLI profiles. The extension never sees these credentials. The Databricks CLI: remove those dedicated profiles there if you no longer need them.

    To reset completely: disconnect each workspace, clear the import and diagnostics, remove site access (here or in the browser's extension details), and close the browser to drop session secrets. Removing the extension deletes everything it stored.
